Use case: When testing my packages, I have folders for mini-projects which each contain a package.json file which contain the project to test as one of the package.json dependencies:

File structure:

project-monorepo/
- packages/
- my-project/
- src/
- test/
- fixtures/
- my-project-test/
- package.json // Contains `"my-project": "link:../../../my-project"`
- test.js // import myProject from 'my-project'; myProject.functionToTest()
- pnpm-workspace.yaml // packages: ['package/*']

When running pnpm install from within one of these mini-projects (e.g. project-monorepo/packages/test/fixtures/my-project-test), pnpm currently tries to install all the workspace dependencies based on the pnpm-workspace.yaml file. I'm looking for an option to force pnpm to only install the mini-package's dependencies and ignore the pnpm-workspace.yaml file in the root of project-monorepo (i.e. to install the dependencies of the mini-project as if the pnpm-workspace.yaml didn't exist). I tried browsing through pnpm install --help but couldn't find an option for this.

Currently, my workaround is to specify the fixtures path in my pnpm-workspace.yaml file and use pnpm install --filter ., but it would be optimal to not have to specify these fixture folders in my pnpm-workspace.yaml file.

After browsing through the source code, I think I've found the option I'm looking for: --ignore-workspace (e.g. pnpm --ignore-workspace install)

Perhaps it might be a good idea to make this more visible in the documentation/help commands? (since pnpm install --help didn't make any mention of this command)

raulfdm

Oct 30, 2023

-

I was having a similar issue: I had a published library and an app that consume this package from the registry (not using workspace: protocol) and I realized when I installed the dependencies, pnpm was linking the package anyways.

While reading the docks to understand why the hack is that, I found this option:

link-workspace-packages

Default: true

Type: true, false, deep

If this is enabled, locally available packages are linked to node_modules instead of being downloaded from the registry. This is very convenient in a monorepo. If you need local packages to also be linked to subdependencies, you can use the deep setting.

Else, packages are downloaded and installed from the registry. However, workspace packages can still be linked by using the workspace: range protocol.

source: https://pnpm.io/npmrc#link-workspace-packages

In other words, if the app and the package is in the same repository, pnpm will link the package in the app no matter if we're using the workspace protocol or not.

When I set --link-workspace-packages=false in my .npmrc, I finally was able to get it from registry.

@zkochan please don't get me wrong for what I'm about to say. I do understand the idea behind doing this automatically but IHMO (nobody asked but here we're), this is a terrible default behavior. I'd rather to explicitly inform pnpm about if I want the packages being linked or not using the workspace protocol explicitly instead having both workspace protocol AND versioned behaving the same.
